# TTS 엔진 교체 검토 (9/17)

## 문제

BE-FEAT-017·018에서 도슨트 음성(한글 240개 + 영문 238개, 총 478개)을
`edge-tts`(Microsoft Edge 브라우저의 TTS 기능을 역엔지니어링한 **비공식**
클라이언트)로 만들었다. 공식 API가 아니라 공모전 제출작에 써도 되는지
이용조건이 불명확하다(소피 발견, PR #49 리뷰).

## 실제 분량 확인

한글+영문 간단히·자세히 4종 합계(120곳 기준, `place_info` 실측):

| 필드 | 글자수 |
|---|---|
| 간단히 Ko | 23,731 |
| 자세히 Ko | 103,561 |
| 간단히 En | 61,433 |
| 자세히 En | 252,822 |
| **합계** | **441,547** |

## 검토한 대안

| 방식 | 무료 한도 | 441,547자 대비 | 한국어 지원 |
|---|---|---|---|
| **Azure Speech(F0)** | 월 500,000자(뉴럴, 만료 없음) | 88% 소진 — 재작업·재생성 여유 거의 없음 | 공식, ko-KR 뉴럴 다수 |
| **Google Cloud TTS** | 월 1,000,000자(Standard/Neural2) | 44% 소진 — 여유 충분 | 공식, ko-KR Standard/Neural2 |
| **Piper**(로컬 오픈소스) | 무제한(로컬 실행) | 해당 없음 | **비공식/커뮤니티 모델 의존** — 공식 배포판에 한국어가 일관되게 포함 안 됨(문서마다 다름), HuggingFace의 `neurlang/piper-onnx-kss-korean` 같은 커뮤니티 모델을 써야 할 수 있음. 품질·라이선스 재확인 필요, 로컬 Python 셋업 시간 소요 |
| **Kokoro**(로컬 오픈소스) | 무제한(로컬 실행) | 해당 없음 | **한국어 지원 불명확** — 공식 v1.0 릴리스는 8개 언어(영어 2종·es·fr·hi·it·ja·pt-BR·zh)만 지원, 한국어 없음. 일부 홍보성 사이트는 한국어 지원을 주장하나 근거 불명, GitHub에 "한국어 지원해달라"는 이슈(#294)가 열려있어 신뢰 불가 |

## 결론 — Google Cloud TTS 추천

- Azure는 무료 한도 88% 소진이라 재생성·수정 여유가 거의 없음(제출 전까지
  원고 수정 가능성 있음을 고려하면 리스크)
- Piper·Kokoro는 한국어 지원 자체가 불확실 — 마감(9/21) 임박한 상황에서
  검증에 시간 쓰는 것도 리스크
- Google Cloud TTS는 한도 여유(44%)·공식 API·한국어 공식 지원 셋 다
  만족하는 유일한 선택지

## 막힌 것 — 사용자 액션 필요

Google Cloud 프로젝트 생성 + Text-to-Speech API 활성화 + 서비스 계정 키
발급은 사용자의 Google 계정 로그인이 필요해 Claude Code가 대신 할 수 없다.

**요청**:
1. https://console.cloud.google.com 에서 프로젝트 생성(또는 기존 프로젝트 사용)
2. "Cloud Text-to-Speech API" 활성화
3. 서비스 계정 생성 → JSON 키 발급
4. 키 파일을 안전하게 전달(예: `.env.local`에 키 경로 또는 내용 추가)

키를 받으면:
1. `generate-docent-audio-ko.ts`/`generate-docent-audio-en.ts`를 Google
   Cloud TTS SDK(`@google-cloud/text-to-speech`) 기반으로 다시 작성
   (ko-KR/en-US Standard 또는 Neural2 보이스로 SunHi·Jenny와 톤 비슷한 것 선정)
2. 기존 edge-tts 478개 mp3 전량 재생성
3. `addRandomSuffix: true`로 이미 고친 업로드 스크립트로 재업로드
4. `place_info`의 `audioUrl*` 필드 값 갱신(같은 필드, URL만 바뀜 — API
   계약·placeDetail.ts 변경 없음)
