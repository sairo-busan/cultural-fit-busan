# 데이터 마트 정의서 (초안)

DB: **MongoDB Atlas (무료 티어 M0)**. 관계형이 아니라 FK 제약은 없음 — 아래 "FK"는 다른 컬렉션의 `_id`를 값으로 저장만 해두는 참조 필드를 뜻한다.

## 레이어 구조

```
[TourAPI] → places (raw)  ─┐
                            ├─ 서비스 응답 (API 조합, DB 컬렉션 아님)
[유나·태무 태깅] → placeTags ┘
```

- `places`: TourAPI 원본을 거의 그대로 적재. 배치 동기화 대상(`areaBasedSyncList2`).
- `placeTags`: 사람이 채우는 큐레이션 데이터. 거의 안 바뀜.
- 클라이언트가 받는 실제 응답은 두 컬렉션을 `contentId`로 조인한 JSON — 별도 컬렉션으로 만들지 않고 API 라우트에서 조합.

이미지는 별도 스토리지에 옮기지 않고 TourAPI가 주는 URL을 그대로 저장·서빙한다 (8/20 latency 테스트로 확인 완료, `docs/decisions` 아님 — 회의록 참조).

## 1. `places` — Raw 레이어

Source: `areaBasedList2`/`areaBasedSyncList2`(목록·좌표) + `detailCommon2`(개요) + `detailIntro2`(운영정보) 를 `contentId` 기준으로 병합해서 저장.

| 필드 | 타입 | 출처 API | 비고 |
|---|---|---|---|
| `_id` | string | contentid | **PK.** TourAPI contentId를 그대로 씀 |
| `contentTypeId` | string | areaBasedList2 | 12 관광지 / 14 문화시설 / 15 축제행사 / 32 숙박 / 39 음식점 등 |
| `title` | string | areaBasedList2 | |
| `addr1` / `addr2` | string | areaBasedList2 | |
| `areaCode` / `sigunguCode` | string | areaBasedList2 | |
| `mapX` / `mapY` | number | areaBasedList2 | 클라이언트 haversine 계산용. 서버가 능동 위치추적하는 게 아니므로 저장은 무방 |
| `firstImage` / `firstImage2` | string \| null | areaBasedList2 | TourAPI URL 그대로, 별도 스토리지 없음 |
| `cpyrhtDivCd` | string | areaBasedList2 | 공공누리 라이선스 타입, 출처표기용 |
| `tel` | string | areaBasedList2/detailCommon2 | |
| `homepage` | string \| null | detailCommon2 | |
| `overview` | string \| null | detailCommon2 | 개요 설명 |
| `operationInfo` | object | detailIntro2 | **원본을 그대로 저장** — `contentTypeId`마다 필드가 다 달라서(관광지는 주차·반려동물, 숙박은 체크인시간 등) 타입 고정 안 함. NoSQL의 유연함을 여기서 씀 |
| `eventStartDate` / `eventEndDate` | string \| null | searchFestival2 | `contentTypeId=15`(축제)만 해당 |
| `lDongRegnCd` / `lDongSignguCd` / `lclsSystm1~3` | string | areaBasedList2 | 분류 코드 |
| `modifiedTime` | string | areaBasedList2 | TourAPI 원본 수정시각 |
| `showFlag` | string | areaBasedSyncList2 | **"1"이 아니면 비노출/삭제 처리** — 동기화 배치가 이 필드로 판단 |
| `images` | string[] | detailImage2 | 원본 이미지 URL 목록 (firstImage 1장 외 추가 이미지) |
| `info` | {name, text}[] | detailInfo2 | 입장료·이용안내 등 반복 항목. `text`가 빈 문자열인 항목은 저장 시 제외 |
| `syncedAt` | Date | (자체) | 우리 시스템이 마지막으로 가져온 시각 |

인덱스: `{ areaCode: 1, contentTypeId: 1 }` (목록 조회용)

`lDongRegnCd`/`lDongSignguCd`(지역명), `lclsSystm1~3`(분류명) 코드를 사람이 읽는 라벨로 바꿀 땐 매 요청마다 `ldongCode2`/`lclsSystmCode2`를 호출하지 않고, 부산 범위(시군구 16개·분류 대분류 10개)만 한 번 받아서 코드 상수 파일(`src/lib/tourApiCodes.ts` 등)로 박아두는 방향. (`docs/TourAPI_오퍼레이션_정리.md` 참고)

## 2. `placeTags` — 태깅 레이어 (유나·태무)

`추천_알고리즘_명세서_v2.md`의 5·8·10·11번 섹션에서 실제로 계산에 쓰는 필드 전부.

| 필드 | 타입 | 비고 |
|---|---|---|
| `contentId` | string | **FK** → `places._id` (참조 필드, 제약 없음) |
| `noiseLevel` | number 1~5 | 분위기 축(Q/V) |
| `crowdLevel` | number 1~5 | |
| `crowdPeak` / `crowdCalm` | string | 시간대, 상태 막대 계산용 |
| `localDepth` | number 1~5 | 로컬 축(L/F) |
| `englishSupport` | number 0~5 | 로컬 축(L/F) |
| `spiceLevel` | number 0~5 | 음식 축(M/H). 0 = 음식점 아님 → 매운맛 축 표시 안 함 |
| `weatherType` | "indoor" \| "outdoor" | 날씨 보정용 |
| `bestTime` | string | 예: "night" |
| `placeType` | "식음형" \| "시장형" \| "해양야경형" \| "문화역사형" | 상태 막대 표시 축 결정 |
| `fitSolo` | number 1~5 | 혼자 앉기 좋은 곳 카테고리용 |
| `tipType` / `tipHeadline` | string \| null | F3 문화충돌 안내 |
| `info` | string[] | 이용 방법 3단계 (F4) |
| `pro` / `con` | string | 실체험 요약 |
| `whyKo` / `whyEn` | string | 추천 이유 문장 재료 |
| `coverage` | number 0~100 | **자동계산** — 태깅 완성도(명세서 3번 섹션 규칙대로 산출), 70+ 정상노출/40~69 하향/40미만 Hard Filter |
| `taggedBy` | string | 유나/태무 작업 추적용 |
| `taggedAt` / `updatedAt` | Date | |

인덱스: `{ contentId: 1 }` unique

## 3. 서비스 응답 (DB 컬렉션 아님)

`GET /api/places/:contentId` 같은 라우트가 `places` + `placeTags`를 `contentId`로 합쳐서 내려주는 형태. 예:

```json
{
  "contentId": "129156",
  "title": "가덕도 등대",
  "mapX": 128.8295937487,
  "mapY": 35.0006471157,
  "firstImage": "http://tong.visitkorea.or.kr/...",
  "noiseLevel": 2,
  "coverage": 85,
  "whyKo": "조용한 곳을 찾으신다면"
}
```

`placeTags`가 아직 없는(태깅 안 된) 장소는 `coverage < 40`으로 취급해 Hard Filter로 제외.
