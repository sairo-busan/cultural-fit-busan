# FE-FEAT-019: 링크 저장 실험 화면 (lab/link-save)

링크 하나에서 부산 장소 후보를 뽑아 지도에서 확인하고 저장하는 숨은 실험 화면. 링크마다 장소를 자동으로 찾을 수 있는지 확인하는 것이 목적이다.

## Problem

10/20 회의 할 일: SNS · 지도 링크를 저장한 장소로 바꿀 수 있는지 확인. DOCS-002 조사만으로는 링크별로 장소가 실제로 뽑히는지 알 수 없다.

- 기존 저장(`cfb_saved`)은 카탈로그 contentId 만 받는다. 카탈로그 밖 장소는 저장 목록에서 빠진다.
- 앱 빌드는 정적 export 라 키를 쓰는 호출은 Vercel API 를 거쳐야 한다(`apiUrl`).

## 링크별 처리

| 링크 | 단서 | 장소 확정 |
|---|---|---|
| YouTube (`watch` · `youtu.be` · `shorts`) | Data API `videos.list` 의 설명란 — `📍` 줄 · `📍` 아래 목록(`-` · `ㄴ`) · 번호 줄(`1. 가게명` + `📍`) · 타임스탬프 줄 · 해시태그. 제목의 괄호 · `\|` · `ㅣ` 뒤 목록 | 카카오 키워드 검색 1건씩 |
| 구글 지도 `/maps/place/<이름>` | 주소 속 이름 | 〃 |
| 카카오 · 네이버 지도 | 장소 페이지 `og:title` | 자동 요청이 막혀(네이버 429 · 카카오 400) 못 찾음으로 간다 |
| Instagram · Facebook · TikTok · 기타 | 공식 경로에 장소 단서 없음 | 못 찾음 → 직접 찾기 |

- 단축 링크(youtu.be · naver.me · kko.to · maps.app.goo.gl)는 최대 5번 따라가고, 매 단계 호스트가 허용 목록에 있어야 한다. `https` 만 받는다.
- 설명란 원문은 응답에 담지 않고 저장하지 않는다. 저장하는 것은 링크 · 영상 제목 · 사용자가 고른 장소 이름과 id.

| 출처 이름 | 자동 후보 대상이 아닌 링크도 호스트로 Instagram · TikTok · Facebook 표시 | L3 에서 "링크" 로만 보여 출처를 알 수 없었음 |

| 삭제 | 링크 삭제는 영상 상세 ⋯, 장소 하나 삭제는 펼친 장소 줄의 "이 장소 삭제". 둘 다 확인 창(위험색). 마지막 장소를 지워도 링크는 남는다(장소 미확정) | 링크와 장소를 따로 지울 수 있어야 한다 |

## Acceptance Criteria

1. YouTube · 구글 지도 링크에서 후보가 나오고, 그 밖의 링크는 직접 찾기로 간다.
2. 허용 목록 밖 호스트 · `http` 링크로는 서버가 요청을 보내지 않는다.
3. 후보를 고르고 저장하면 `cfb_link_saves` 에 링크 단위로 남는다(같은 링크는 덮어쓴다).
4. L3 · 영상 상세에서 저장한 곳을 다시 보고 지도로 연다.
5. 기존 저장 탭 · S20 · 피드 동작은 바뀌지 않는다.
6. `npm run lint` · `tsc` · 웹 빌드 · `BUILD_TARGET=app` 빌드 통과.
