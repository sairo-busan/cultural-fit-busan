# Tickets

이 폴더는 AI 주도 개발의 **작업 명세(티켓)** 를 담는다. 모든 기능/버그 작업은 티켓에서 시작한다.

> 티켓은 작업 가이드다. 실제 코드 변경은 일반 git/PR 흐름으로 커밋한다.
> (원한다면 `docs/`를 `.gitignore`에 넣어 로컬 전용으로 운영해도 됨.)

---

## 작성 위치·네이밍

- 마일스톤 폴더 아래: `docs/tickets/MS-XX/`
- 파일명: `{TYPE}-{NNN}_{short_name}.md`
  - TYPE: `FEAT` | `BUG` | `TASK`
  - 예: `docs/tickets/MS-01/BUG-001_subscription_renewal_fix.md`
- 템플릿: [_TEMPLATE.md](./_TEMPLATE.md) 복사해서 작성.

---

## 티켓 생성 → 완료 흐름

```
1. _TEMPLATE.md 복사 → docs/tickets/MS-XX/{TYPE}-{NNN}_{name}.md 작성
2. 겹침 확인: main에 아직 안 머지된 브랜치가 있으면, 이번 티켓이 건드릴 파일을
   그 브랜치도 건드리는지 먼저 확인(`git diff main {미머지브랜치} -- {파일}`).
   겹치면 그 브랜치가 시그니처/로직을 어떻게 바꿔놨는지 먼저 파악하고,
   그 브랜치 머지 후에도 이번 구현이 여전히 맞는지 미리 반영하거나 사용자에게 알린다.
3. 브랜치 생성: Feat/기능명  (1 티켓 = 1 브랜치)
4. AI: 근본원인·수정파일·구현계획 제시 → 구현
5. 검증: 타입체크 (+ 빌드) + 수동 스모크
6. 리포트: docs/_internal/analysis/{전체티켓파일명}_report.md
7. PR 생성 (사용자 승인 후 커밋/푸시 — 자동배포 브랜치 주의)
8. 운영 배포·검증 → DoD 충족 시 Done
```

DoD 상세: [../QA_AND_DONE.md](../QA_AND_DONE.md).

---

## 규칙 요약

- **1 티켓 = 1 브랜치 = 1 PR.** 여러 티켓 합치지 않음.
- 티켓은 **작게**(1~3 파일, 단일 논리 변경). 크면 분할.
- 티켓 텍스트가 요구사항의 단일 진실. 범위 밖 변경 금지.
- 핫픽스와 기능 개발 분리.
- 파생 산출물은 티켓 전체 파일명 상속(축약 금지).
- 멀티레포 기능은 **같은 티켓 ID로 양쪽 연결** (→ `../AI_AGENT_RULES.md` §3.1).
